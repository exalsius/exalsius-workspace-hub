# Align llm-inference to llm-d 0.9.0: router charts, and we own the model server

The `llm-inference` templates were built on llm-d 0.6.0 against two upstream
Helm charts — `llm-d-incubation/llm-d-infra` (the shared gateway) and
`llm-d-incubation/llm-d-modelservice` (the vLLM pods), with the GAIE
`inferencepool` chart between them. **Both were deprecated in llm-d 0.7.0** and
listed in that release's component matrix with version `N/A`; the `llm-d-infra`
repository was archived in May 2026. Neither appears in the 0.8.0 or 0.9.0
component tables.

This ADR records the move to llm-d **0.9.0** (released 2026-08-17).

## What upstream replaced them with

llm-d's deployment story is now *guides*: Helm for the router, Kustomize for the
model server.

| Was | Is |
| --- | --- |
| `llm-d-infra` chart | `guides/recipes/gateway/agentgateway` — a bare `Gateway` manifest |
| GAIE `inferencepool` chart | `oci://ghcr.io/llm-d/charts/llm-d-router-gateway` |
| `llm-d-modelservice` chart | `guides/recipes/modelserver` — a plain `Deployment`, no chart |
| EPP `llm-d-inference-scheduler` | renamed `llm-d-router-endpoint-picker` (0.8.0) |
| `ghcr.io/llm-d/llm-d-cuda` | upstream `vllm/vllm-openai` (0.8.0) — but we stay on the llm-d build, see [ADR-0009](0009-llm-d-model-server-image.md) |

## Decisions

**Take the router chart; port the Gateway.** `llm-d-router-gateway` renders the
`InferencePool`, the endpoint picker and its RBAC, all named off `.Release.Name`.
The `Gateway` has no chart any more, so `llm-d-infra/templates/gateway.yaml` is a
faithful port of what the archived subchart rendered at v1.4.0 — same name, same
three listeners, same `AgentgatewayParameters` pinning the data-plane Service to
ClusterIP — minus the provider matrix (istio/gke/kgateway) we never used. The
port was verified by diffing the rendered `Gateway` and `AgentgatewayParameters`
against the pre-change output: **both specs are byte-identical.**

**Own the vLLM workload.** *(It is a `Deployment` in this ADR; [ADR-0010](0010-always-leaderworkerset-and-the-nodesperreplica-toggle.md) makes it a `LeaderWorkerSet` so one shape covers single- and multi-node. The reasoning for owning it is unchanged.)* Upstream's successor to modelservice is a Kustomize
base, not a chart, so there is nothing to depend on. Writing the `Deployment`
here is not a workaround — it is the point. modelservice let the operator reach
GPU count only *indirectly*, by injecting into `parallelism.tensor` and letting
the subchart derive the accelerator request, and `cpu`/`memory` could not be
injected at all because they sat inside a list path
([ADR-0002](0002-llm-inference-prerequisite-and-umbrella-mapping.md)). Owning the
container spec gives every `_exalsius` field a direct target, so the
`WorkspaceClass` drops `resourceInjection` entirely.

**Keep body-based routing native to agentgateway.** *(Superseded by
[ADR-0008](0008-agentgateway-model-api-replaces-model-registry.md), which
retires our own policy in favour of agentgateway's `AgentgatewayModel` — the
conclusion that IPP is the wrong fit still holds.)* llm-d replaced GAIE's BBR
with the Inference Payload Processor (IPP), matching on
`X-Gateway-Base-Model-Name`. We do **not** adopt it: the `payload-processor`
chart ships only `istio` and `gke` providers, and agentgateway reads the request
body itself. IPP exists to give body-blind gateways an ext_proc; adopting it here
would add a pod, an RBAC surface and a network hop to replace a policy that
already works. `X-Gateway-Model-Name` therefore stays, and so does the
`bbr-managed` ConfigMap label — with BBR and IPP both out of the discovery path,
that label is a private contract between our two charts, not an upstream one.

**Keep our own HTTPRoutes.** `llm-d-router-gateway` can render an `HTTPRoute`
(`httpRoute.create`), but only one, with no `sectionName`. This stack needs one
route per gateway listener so the API-key policy can gate `external` while
leaving `internal` open, so the flag stays off.

## Consequences

- **Both vendored-chart patches are gone.** `charts/_README.md` documented
  `global.deploymentName` hacks against `inferencepool` and `modelservice`,
  needed because neither honoured the release name. The router chart names
  everything `<release>-epp` natively, and the Deployment is ours. `llm-d-model`
  now vendors one unmodified chart.
- **Pool and pods are wired in one place.** `igw.router.modelServers.matchLabels`
  is both the `InferencePool` selector and the labels stamped on the vLLM pods.
  Previously the same label had to be repeated in `ms.modelArtifacts.labels` and
  `ip.inferencePool.modelServers.matchLabels`, and a mismatch silently produced a
  pool with no endpoints. Helm cannot template subchart values, so this stays a
  literal rather than being derived from the release name; the default assumes
  one model per namespace, which is how the operator deploys workspaces.
- **`model.uri` is gone.** vLLM takes the Hugging Face repo id directly, so the
  two user-facing fields (`ms.modelArtifacts.uri` + `.name`) collapse into
  `model.name`. Serving from a pre-populated volume is now
  `model.source.claimName`, replacing `uri: pvc://…`.
- **Model cache defaults unchanged.** modelservice put the weights in an
  `emptyDir` sized from `modelArtifacts.size`; the new chart does the same,
  sized from the injected `storage`. `cache.mode: pvc` is opt-in, and the chart
  refuses to render `ReadWriteOnce` + >1 replica rather than shipping pods that
  would deadlock on multi-attach.
- **Driver floor.** llm-d 0.7.0 moved the CUDA images to 13.0.2, which requires
  **NVIDIA driver ≥580**. Nodes below that must be upgraded before this version
  is deployed. This is the one change that can break a working cluster.
- **CRDs move with it** — GAIE v1.4.0 → v1.5.0, agentgateway v1.0.0 → v1.4.1
  (v1.1.0 in this ADR, moved on again by ADR-0008)
  ([ADR-0004](0004-inference-crds-vendored-in-llm-d-infra.md)). Helm never
  upgrades `crds/`, so clusters carrying the old bundles keep them until a manual
  CRD update.
- **The umbrella-mapping half of [ADR-0002](0002-llm-inference-prerequisite-and-umbrella-mapping.md)
  is superseded.** Its prerequisite/shared-gateway reasoning still stands; the
  `resourceInjection` mapping it describes no longer exists.
